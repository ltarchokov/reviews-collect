# Сбор отзывов с площадок

Инструмент — CLI `collect.py` в корне проекта. Скилл только маршрутизирует
запрос в его аргументы и объясняет, чему в данных нельзя верить.

## Первым делом: запуск только через .venv

```bash
.venv/bin/python collect.py --list
```

Не `python3` — системный Python на macOS закрыт для установки пакетов
(PEP 668), а нужны `curl_cffi` и `selectolax`. Если `.venv` нет:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

## Разбор запроса пользователя

| Что сказал пользователь | Куда это идёт |
|---|---|
| название площадки | первый позиционный аргумент (`wb`, `uteka`, …) |
| бренд, товар, категория | второй позиционный — поисковый запрос |
| артикулы WB | `--nm 119396077 148815731` |
| ссылки на товары Ютеки | `--url https://uteka.ru/product/...` |
| «за период», «с января», «в 2025» | `--period 2025-01..2025-08` |
| «негатив», «1–3 звезды», «плохие» | `--stars 1-3` |
| «с фото», «с видео» | `--media photo` / `video` / `any` |
| «где упоминают X, Y» | `--contains "X,Y"` |
| «развёрнутые», «от N символов» | `--min-len 500` |
| «о продавце», «о сервисе» | `--about seller` / `service` |
| «побольше», «пошире охват» | `--products 40` (WB), `--pages 2` |

Сравнение брендов — это несколько прогонов в один каталог с разными
запросами, затем склейка по колонке `brand`; схема одна, датасеты
сходятся без правок.

## Площадки: что работает

| Аргумент | Площадка | Состояние |
|---|---|---|
| `wb` | Wildberries | ✅ проверен на живых данных |
| `uteka` | Ютека | ✅ проверен на живых данных |
| `irecommend` | iRecommend | ⚠️ написан по разведке, **не проверен** |

Остальные восемь площадок задания не подключены. Прежде чем обещать
пользователю сбор с них — прочитай `references/blocked.md`: часть
закрыта антиботом, а у одной отзывов физически нет. Не предлагай
«просто попробовать»: причины конкретные и известные.

## Порядок работы

Это сервис, а не разовая аналитика. Один и тот же запрос обязан давать
один и тот же по форме результат.

1. Определи площадку. Если пользователь её не назвал — спроси, не
   угадывай: данные с разных площадок несопоставимы по глубине.
2. Прочитай `references/<площадка>.md` — там ограничения именно этой
   площадки. Без этого легко выдать смещённую выборку за полную.
3. **Разведай структуру, если запрос широкий** (см. следующий раздел).
4. Собери команду по таблице выше и запусти.
5. Отдай пользователю ответ **строго по шаблону ниже**.

### Разведка до сбора — обязательна при широком запросе

Запрос «собери отзывы по свитерам» широкий: непонятно, чей бренд, и на
площадке под этим словом лежит несколько разных подкатегорий. Не
угадывай ни то, ни другое — спроси, но **спроси по фактам источника**:

```bash
.venv/bin/python collect.py wb "свитер" --explore
```

Команда ничего не собирает, она показывает, что в источнике есть:
подкатегории с названиями, бренды, продавцы — и сколько в каждом
карточек и отзывов. Дальше уточняющий вопрос строится на этих цифрах,
а не на предположении.

Так это выглядит: по запросу «свитер» площадка отдаёт 110 690 карточек,
а внутри — девять подкатегорий: Свитеры (119 карточек, 63 тыс. отзывов),
Водолазки (7, 37 тыс.), Кофты (5, 17 тыс.), Свитшоты, Джемперы,
Пуловеры, Кардиганы и ещё две мелкие. Вопрос пользователю тогда
конкретный: собирать всё вместе или разбить по подкатегориям, и какой
бренд — потому что брендов в выдаче 112.

**Когда разведка нужна:**

- бренд не назван — почти всегда, иначе соберём чужой ассортимент;
- названа категория, а не конкретный товар («свитеры», «уход за лицом»);
- пользователь просит «сравнить» и не назвал, с чем именно;
- объём заранее непонятен, а прогон дорогой по времени.

**Когда не нужна:** назван бренд и узкая категория, даны артикулы или
ссылки, либо пользователь уже выбрал разрез в предыдущем сообщении.

Разведка есть не у всех площадок — она требует, чтобы в выдаче были
разрезы. Если площадка её не умеет, `--explore` скажет об этом прямо.

### Сужение

Выбранное пользователем идёт в аргументы: `--subject «Водолазки»`,
`--brand «ТВОЕ»`, `--supplier «название»`. Каталог результата включает
сужение — `out/wb/свитер--водолазки/`, — поэтому разные разрезы одного
запроса не затирают друг друга и на них можно ссылаться позже.

### Шаблон ответа — не отклоняйся

```
<Площадка>, <что собирали>

- N отзывов по M карточкам
- Заявлено площадкой: K — взято X%
- Негатив 1–3: Y% по данным площадки

Главное из сводки: <3–5 строк — верхние дефекты и разброс по карточкам>

Файлы: out/<площадка>/<запрос>/ — reviews.csv, products.csv, summary.md
<одна оговорка, если она есть в сводке>
```

**Никакого анализа сверх сводки.** Не пиши на ходу скрипты, чтобы
посчитать темы, доли по карточкам или вытащить цитаты: всё это уже
считает `collect.py` одинаково при каждом запуске — разделы «В чём
претензия», «Цитаты по главным темам», «Разброс по карточкам».
Импровизированный разбор каждый раз даёт другой результат, а это
ломает сервис: пользователь не может опереться на цифру, которую
в следующий раз посчитают иначе.

Если пользователь просит разрез, которого в сводке нет, — это заявка
на доработку `report.py`, а не повод посчитать один раз руками. Скажи
об этом прямо и предложи добавить разрез в инструмент.

### Если запрос неточный

Не додумывай молча — уточни или поправь, назвав причину:

- площадка не названа → спроси какая;
- бренд написан латиницей, а площадка русская (или наоборот) → возьми
  оба варианта в один прогон;
- категория названа словом, которого нет в поиске площадки → предложи
  формулировку, которая даст выдачу;
- просят площадку из `references/blocked.md` → назови причину, не
  пробуй «на всякий случай»;
- просят период глубже, чем площадка отдаёт → скажи, какая глубина
  реально доступна, до сбора, а не после.

## Чему в данных нельзя верить

Три правила, нарушение которых даёт правдоподобный, но неверный ответ.

**Не выдавай распределение оценок из `reviews.csv` за распределение по
карточке.** На WB собранный срез показывает негатив втрое сильнее, чем
карточка целиком (6.6% против 2.2%). Для процентов есть таблица
«Смещение выборки» в `summary.md`, она считается от данных площадки.

**Не строй динамику за годы по данным WB.** Он отдаёт последнюю тысячу
отзывов на карточку: у товара с 241 тысячей отзывов срез покрывает
месяцы, а не годы. У Ютеки глубина полная, с 2018 года — там можно.

**Отделяй претензии к продукту от логистики, подделок и сервиса.**
`summary.md` делит негатив на темы грубой разметкой по словам. Это
первый срез, требующий проверки глазами, а не классификатор. Без
разделения бренд получает претензии за работу склада.

## Если сбор дал ноль

Пустой результат — это три разных случая, и путать их нельзя:

- **площадка закрыта** (`недоступен`, `не пробились`) — это не «отзывов
  нет». Скажи пользователю, что закрыта именно площадка;
- **фильтры срезали всё** — в выводе видно `собрано N → после фильтров 0`.
  Предложи ослабить фильтр, а не пересобрать;
- **у товара действительно нет отзывов** — видно по `reviews_declared: 0`
  в `products.csv`.
