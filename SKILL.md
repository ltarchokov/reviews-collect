# Сбор отзывов с Wildberries

Инструмент — CLI `scripts/collect.py` внутри этого скилла. Скилл ведёт
пользователя по одному и тому же пути: уточнить срез → собрать → отдать
книгу Excel. Ничего сверх этого пути не собирается и не считается: один
запрос обязан давать один и тот же по форме результат у любого коллеги.

Площадка одна — Wildberries. Если просят другую (Ozon, Яндекс Маркет,
Ютека, Lamoda, Золотое Яблоко и прочие), скажи, что скилл собирает
только с Wildberries, и предложи собрать с него. Не пробуй «на всякий
случай» и не пиши парсер на ходу: другие площадки либо закрыты
антиботом, либо не проверены, и это известно заранее.

## Примеры в этом файле — не задания

Все команды и названия ниже («свитер», «ТВОЕ», «Водолазки», артикулы)
— иллюстрации формата, а не то, что нужно собрать. Подставляй только
то, что назвал пользователь. Если он ещё ничего не назвал — иди в
шаг 0 и спроси; ни одна команда из примеров не запускается «для
проверки» или «чтобы показать, как работает».

## Как вызывать инструмент

Каталог скилла — тот, где лежит этот `SKILL.md`; ниже он обозначен
`$SKILL`. Все команды ниже записаны сокращённо через слово `collect`,
которое означает полный вызов:

```
$SKILL/scripts/.venv/bin/python $SKILL/scripts/collect.py
```

На Windows — `$SKILL\scripts\.venv\Scripts\python.exe`. Подставляй
абсолютный путь: каждая команда выполняется в новой оболочке.

Запускай из корня рабочего проекта пользователя — каталога, в котором
открыта сессия агента. Если сессия открыта внутри каталога скилла
(`.../skills/reviews-collect/...`), поднимись до корня проекта, который
его содержит. Результат кладётся в `out/` относительно корня, а не
внутрь скилла: скилл обновляется из репозитория, и данные в нём
потерялись бы.

Если `$SKILL/scripts/.venv` нет — создай один раз:

```bash
cd $SKILL/scripts && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

Не `python3` напрямую: системный Python на macOS закрыт для установки
пакетов (PEP 668), а нужны `curl_cffi` и `openpyxl`.

## Стандартный ход работы

Четыре шага, всегда в этом порядке, плюс шаг 0 для тех, кто пришёл без
конкретного запроса. Шаг 2 пропускается только в случаях, названных ниже.

### Шаг 0. Знакомство

Срабатывает, когда пользователь начинает без задачи: «давай начнём»,
«что ты умеешь», «помоги собрать отзывы», «как это работает». Цель —
чтобы человек, впервые открывший скилл, за одно сообщение понял, что
получит, и за один раунд вопросов дал всё нужное для старта. Команд на
этом шаге не выполняй: окружение проверится само при первом сборе,
а человек ждёт текста, не прогресса в терминале.

Сначала представление — этим текстом, без пересказа своими словами,
чтобы у всех коллег знакомство было одинаковым:

```
Я собираю отзывы покупателей с Wildberries и отдаю книгу Excel:
сводка с темами негатива и цитатами, все отзывы, отдельно негатив,
карточки товаров.

Единица сбора — один бренд в одной категории: «водолазки ТВОЕ»,
а не «свитеры вообще». Достаточно назвать бренд — я покажу, в каких
категориях он представлен на WB, и вы выберете. Или назовите
категорию — покажу, какие бренды в ней есть. Сбор занимает
две-три минуты.

WB отдаёт последнюю тысячу отзывов на карточку, поэтому срез свежий:
динамику за годы по нему не построить, темы и цитаты — можно.
```

Затем один раунд вопросов средствами окружения (если инструмент
вопросов умеет несколько вопросов за раз — оба сразу, иначе по одному,
в этом порядке). Формулировки фиксированные:

1. **Что ищем.** «Что ищем: бренд, категория, конкретный товар или
   артикулы? Например „свитшоты ТВОЕ“ или „сыворотка с витамином C“.»
   Свободный ответ.
2. **Срез.** «Какие отзывы нужны?» Варианты: все отзывы (стандарт,
   рекомендуемый), только негатив 1–3 (`--stars 1-3`), за период
   (`--period`, границы уточни следующим вопросом), с фото
   (`--media photo`). Это единственное место, где о фильтрах спрашиваем
   сами: пользователь попросил провести его по вопросам, а не поставил
   задачу.

После ответов работа идёт по шагам 1–4 как с обычным запросом. Не
повторяй представление и не переспрашивай то, что уже ответили.

Если пользователь спросил «что ты умеешь» и явно не собирается ничего
собирать сейчас — представление без вопросов, и в конце одна строка:
«Назовите бренд или категорию — начнём».

### Шаг 1. Разобрать запрос

| Что сказал пользователь | Куда это идёт |
|---|---|
| бренд, категория, товар | поисковый запрос — второй позиционный аргумент, **всё, что назвал пользователь, вместе**: «летние шины пирелли» → `"pirelli летние шины"`, «по кроссовкам найк» → `"кроссовки nike"`. Бренд из запроса не выбрасывать: по «летние шины» выдача даёт 92 тысячи карточек, и в первых двухстах нужного бренда не окажется |
| сезон, модель, объём внутри категории («летние», «Powergy», «500 мл») | `--name "летн"` — по вхождению в название карточки, потому что категория WB одна на все сезоны («Шины автомобильные») |
| ссылки на товары WB | `--url <ссылка> <ссылка>` — артикул берётся из ссылки, поиск и разведка не нужны |
| артикулы WB | `--nm 119396077 148815731` |
| «за период», «с января», «в 2025» | `--period 2025-01..2025-08` |
| «негатив», «1–3 звезды», «плохие» | `--stars 1-3` |
| «с фото», «с видео» | `--media photo` / `video` / `any` |
| «где упоминают X, Y» | `--contains "X,Y"` |
| «развёрнутые», «от N символов» | `--min-len 500` |
| «побольше», «пошире охват» | `--products 40`, `--pages 2` |

Фильтры применяются только если пользователь их назвал. Не предлагай
их сам и не спрашивай о них: без фильтров собирается полный срез,
а сузить его в Excel коллега может и без нас. То же с объёмом: без
`--products` инструмент берёт 25 самых отзывных карточек — это
стандарт, и менять его стоит только по просьбе «побольше».

### Шаг 2. Разведка и уточняющий вопрос

Единица сбора — **один бренд в одной продуктовой категории**. Не
«свитеры вообще» и не «весь ассортимент бренда». По запросу «свитер»
в выдаче около сотни брендов: без бренда датасет — смесь чужих товаров
и не отвечает ни на один вопрос. У бренда ТВОЕ 31 категория от футболок
до шлепанцев: сбор целиком смешивает претензии к обуви с претензиями
к белью, а болевые темы у них разные.

Поэтому до сбора запускается разведка:

```bash
collect wb "<бренд>" --explore        # пользователь назвал бренд
collect wb "<категория>" --explore    # пользователь назвал категорию
```

Она ничего не собирает — показывает, что в источнике реально есть
(бренды, подкатегории, продавцы, сколько карточек и отзывов в каждом),
и сама решает, что дальше. Три исхода, каждый напечатан явно:

- **Пользователь назвал бренд, категорий не знает** — обычный случай.
  Разведка узнаёт бренд по выдаче, берёт его название в написании
  площадки (кириллическое «найк» → `Nike`) и показывает категории
  **только этого бренда**. Блок `СПРОСИТЬ У ПОЛЬЗОВАТЕЛЯ`: «выбери категорию».
  Пользователь выбирает — это и есть ответ на его вопрос «в каких
  категориях вообще есть мой бренд».
- **Пользователь назвал категорию** — брендов много. Блок `СПРОСИТЬ
  У ПОЛЬЗОВАТЕЛЯ`: «чей ассортимент нужен». После ответа повтори
  разведку с `--brand` в написании из списка и задай второй вопрос —
  про категорию.
- **Уточнять нечего** — у бренда одна категория (у шинных брендов это
  «Шины автомобильные») или категория уже названа. Блок `ГОТОВО К СБОРУ`
  с готовыми аргументами. Вопрос не задавай, переходи к шагу 3.

Если бренд назван, а в поле brand площадки его нет (другое написание),
разведка перечислит бренды выдачи — возьми написание оттуда.

**Написание бренда.** Пользователи пишут бренд кириллицей, с опечатками
и в любом регистре: «пирели», «найк», «адидас кросовки». В поисковый
запрос это идёт **как написал пользователь**, без исправлений и без
перевода на латиницу: поиск WB переживает опечатки и транслит лучше
догадки, проверено. Правильное написание бренда существует в одном
месте — в списке брендов из разведки; оттуда оно берётся в `--brand`
и в ответ пользователю. Сам инструмент тоже понимает написание
пользователя во флаге `--brand` («пирели» → Pirelli) и пишет об этом
в лог, но это страховка, а не способ работы. Если в списке разведки
нет ничего похожего на названный бренд — покажи список и спроси,
не подбирай.

**Линейки одного производителя.** В списке брендов бывает несколько
похожих: `Pirelli` 157 карточек, `PIRELLI FORMULA` 7, `Pirelli Russia` 20.
Это разные бренды в поле площадки. Бери тот, что назвал пользователь,
в его основном написании и с наибольшим числом отзывов; остальные
назови в ответе одной строкой, чтобы он мог попросить их отдельно.
Не подменяй основной бренд линейкой только потому, что она первой
попалась в выдаче: если разведка по запросу без бренда показала одну
малую линейку, это признак, что бренд не попал в запрос, — вернись
к шагу 1 и добавь его.

**Сезон и модель внутри категории.** Категория WB не различает
«летние» и «зимние»: у шин она одна, «Шины автомобильные». Если
пользователь назвал сезон, модель или объём, сузь по названию карточки:
`--name "летн"`. Разведка с `--name` считает разрезы уже внутри этого
сужения.

**Как задавать вопрос.** Средствами своего окружения для вопросов
пользователю (в Claude Code — `AskUserQuestion`, в Kilo —
`ask_followup_question`, в Cursor — инструмент вопросов агента), а не
текстом в ответе, за которым идёт работа. Если инструмента вопросов
нет — задай вопрос в ответе и закончи ход: следующий шаг только после
сообщения пользователя. Вопрос — тот, что сформулировала разведка; не
переформулируй. Варианты ответа — три верхних значения из разведки по
числу отзывов, с цифрами в том виде, как их напечатал инструмент
(«Водолазки — 12 карточек, 8 400 отзывов»), плюс вариант «другой —
назову сам»: инструменты вопросов обычно вмещают четыре варианта,
а полный список разведки пользователь и так видит в твоём сообщении.
Дождись ответа и только потом продолжай.

**Вариант «собрать всё вместе» не предлагается никогда.** Если
пользователь просит именно его — скажи, что получится смесь, и предложи
разбить на несколько прогонов по одной категории.

**Когда разведку можно пропустить:** названы и бренд, и узкая категория
(«свитшоты ТВОЕ», «брюки INICIO») — тогда сразу сбор, но **обязательно
с `--subject «категория»`**, а не только с `--brand`: поиск по «брюки
INICIO» приносит и платья, и костюмы того же бренда. Инструмент сам
откажется собирать несколько категорий и напечатает их список с
числом карточек — это значит, что название категории не совпало
с предметом WB (у площадки «Брюки», а не «штаны»). Покажи список
пользователю и спроси, какую собирать; не выбирай сам и не включай
`--all-subjects`, если он прямо не просил всё вместе. Также разведка
не нужна, когда даны ссылки `--url` или артикулы `--nm`, либо
пользователь уже выбрал разрез в предыдущем сообщении.

**Режим по ссылкам.** Пользователь сам выбрал товары — уточнять нечего,
сразу шаг 3 без `--brand` и `--subject`:

```bash
collect wb --url "<ссылка 1>" "<ссылка 2>"
```

Принимаются ссылки вида `wildberries.ru/catalog/<артикул>/detail.aspx`
и `.../feedbacks`; ссылку, в которой артикула не нашлось, инструмент
называет в выводе — передай это пользователю, не подбирай товар сам.
Если ссылок больше 25, добавь `--products <их число>`, иначе лишние
отрежутся стандартным лимитом. В ответе вместо «бренд · категория»
пиши «товары по ссылкам, N шт.» и перечисли их по листу «Карточки».

Обычно на уточнение уходит один вопрос, редко два. Не растягивай: один
вопрос на шаг, без дополнительных «а ещё уточните».

### Шаг 3. Сбор

Выбранное пользователем идёт в аргументы: `--brand` и `--subject`
в написании из разведки, при необходимости `--supplier`.

```bash
collect wb "<запрос>" --brand "<бренд из разведки>" --subject "<категория из разведки>" [--name "<слово из названия>"]
```

Например, для запроса «свитер» и выбора «ТВОЕ», «Водолазки»:
`collect wb "свитер" --brand "ТВОЕ" --subject "Водолазки"`.

Каталог результата включает сужение — `out/wb/свитер--твое--водолазки/`
— поэтому разные срезы одного запроса не затирают друг друга.
Ориентир по времени: около 5 секунд на карточку, 25 карточек —
две минуты. Если сбор дал ноль — см. раздел ниже, это четыре разных случая.

Сравнение брендов — несколько прогонов с разными `--brand` в одной
категории. Схема одна, книги сходятся без правок.

### Шаг 4. Ответ

Главный результат — книга Excel, путь к ней инструмент печатает
последней строкой. В ней четыре листа, всегда в этом порядке:

| Лист | Что внутри |
|---|---|
| Сводка | покрытие, смещение выборки, распределение оценок, темы негатива, цитаты, динамика |
| Отзывы | строка = отзыв, русская шапка, фильтр и закреплённая шапка |
| Негатив | те же колонки, только оценки 1–3 — с него обычно начинают читать |
| Карточки | товары в выборке, заявлено и собрано отзывов по каждому |

Рядом лежат `reviews.csv`, `products.csv` и `summary.md` — для склейки
датасетов и для тех, кто без Excel. В ответе пользователю их можно не
называть.

Ответ — строго по шаблону:

```
Wildberries, <бренд> · <категория>

- N отзывов по M карточкам, с содержательным текстом S
- Заявлено площадкой: K, из них с текстом T — взято X% читаемых
- Негатив 1–3: Y% по данным площадки; негативных с текстом Z — выводы о жалобах ниже опираются на них

Главное из сводки: <3–5 строк — верхние дефекты и разброс по карточкам>

Книга: out/wb/<срез>/wb--<срез>.xlsx
<одна оговорка, если она есть в сводке>
```

Цифры берутся из листа «Сводка» (он же `summary.md`): S — строка
«С содержательным текстом», Z — из заголовка раздела «Негатив». Обе
обязательны в ответе: «1007 отзывов» звучит весомо, а тем негатива
за этим стоит 41 текст, и читатель должен это видеть сразу. Доля
негатива — из таблицы «Смещение выборки», колонка «Карточки целиком». Почему —
в разделе о доверии к данным. Покрытие сравнивай с числом отзывов
**с текстом**, а не с общим: общее включает оценки без слов, которых
площадка не отдаёт никому. «418 из 1502» — это не потеря 72%, а все
402 читаемых отзыва; не пиши пользователю про «критичный разброс»,
если сводка говорит, что читаемые взяты полностью.

**Никакого анализа сверх сводки.** Не пиши на ходу скрипты, чтобы
посчитать темы, доли по карточкам или вытащить цитаты: всё это уже
считает инструмент одинаково при каждом запуске. Импровизированный
разбор каждый раз даёт другой результат, а это ломает сервис:
пользователь не может опереться на цифру, которую в следующий раз
посчитают иначе. Если просят разрез, которого в сводке нет, — это
заявка на доработку `scripts/core/report.py`, а не повод посчитать
один раз руками. Скажи об этом прямо.

## Чему в данных нельзя верить

Три правила, нарушение которых даёт правдоподобный, но неверный ответ.
Подробности и грабли площадки — `references/wb.md`, прочитай его
перед первым сбором в сессии.

**Не выдавай распределение оценок из листа «Отзывы» за распределение
по карточке.** Собранный срез показывает негатив втрое сильнее, чем
карточка целиком (6.6% против 2.2%). Для процентов есть таблица
«Смещение выборки» в сводке, она считается от данных площадки.

**Не строй динамику за годы.** WB отдаёт последнюю тысячу отзывов
с текстом на карточку: у товара с 241 тысячей отзывов срез покрывает
месяцы, а не годы. Глубже не пролезть: пагинацию эндпоинт игнорирует,
это проверено — не ищи обход и не обещай его пользователю.

**Отделяй претензии к продукту от логистики, подделок и сервиса.**
Сводка делит негатив на темы грубой разметкой по словам. Это первый
срез, требующий проверки глазами, а не классификатор. Без разделения
бренд получает претензии за работу склада.

Подробнее — `references/analysis.md`.

## Если сбор дал ноль

Пустой результат — четыре разных случая, и путать их нельзя:

- **площадка не отвечает** (`не пробились`) — это не «отзывов нет».
  Скажи, что не отвечает именно площадка, и предложи повторить: 429
  на поиске WB вероятностный, второй запуск обычно проходит;
- **сужение не совпало** — инструмент сам перечисляет, какие категории
  у бренда реально есть в этой выдаче. Передай список пользователю
  и спроси снова, не подбирай за него;
- **фильтры срезали всё** — в выводе видно `собрано N → после фильтров 0`.
  Предложи ослабить фильтр, а не пересобрать;
- **у товара действительно нет отзывов** — видно по колонке
  «Отзывов заявлено» на листе «Карточки».

## Установка скилла у коллег

Скилл самодостаточен: код, зависимости и справочники внутри. Склонировать
из репозитория в каталог скиллов — `.cursor/skills/reviews-collect/` для
Cursor, `.kilo/skills/reviews-collect/` для Kilo, `.claude/skills/reviews-collect/`
для Claude Code (Kilo и Cursor читают и его) — и один раз создать
окружение командой из раздела «Как вызывать инструмент». `.venv`
не копируется между машинами: в нём абсолютные пути. Имя каталога
должно совпадать с `name` в шапке этого файла.
