# Сбор отзывов с площадок

Инструмент — CLI `scripts/collect.py` внутри этого скилла. Скилл ведёт
пользователя по одному и тому же пути: уточнить срез → собрать → отдать
книгу Excel. Ничего сверх этого пути не собирается и не считается: один
запрос обязан давать один и тот же по форме результат у любого коллеги.

## Как вызывать инструмент

Каталог скилла — тот, где лежит этот `SKILL.md`; ниже он обозначен
`$SKILL`. Все команды ниже записаны сокращённо через слово `collect`,
которое означает полный вызов:

```
$SKILL/scripts/.venv/bin/python $SKILL/scripts/collect.py
```

На Windows — `$SKILL\scripts\.venv\Scripts\python.exe`. Подставляй
абсолютный путь: каждая команда выполняется в новой оболочке.

Запускай из корня рабочего проекта пользователя — каталога, в котором
открыта сессия агента. Если сессия открыта внутри каталога скилла
(`.../skills/reviews-collect/...`), поднимись до корня проекта, который
его содержит. Результат кладётся в `out/` относительно корня, а не
внутрь скилла: скилл обновляется из репозитория, и данные в нём
потерялись бы.

Если `$SKILL/scripts/.venv` нет — создай один раз:

```bash
cd $SKILL/scripts && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

Не `python3` напрямую: системный Python на macOS закрыт для установки
пакетов (PEP 668), а нужны `curl_cffi`, `selectolax` и `openpyxl`.
Проверка, что всё живо: `collect --list`.

## Стандартный ход работы

Четыре шага, всегда в этом порядке, плюс шаг 0 для тех, кто пришёл без
конкретного запроса. Шаг 2 пропускается только в случаях, названных ниже.

### Шаг 0. Знакомство

Срабатывает, когда пользователь начинает без задачи: «давай начнём»,
«что ты умеешь», «помоги собрать отзывы», «как это работает», или
просит отзывы, не назвав ни площадки, ни что искать. Цель — чтобы
человек, впервые открывший скилл, за одно сообщение понял, что получит,
и за один раунд вопросов дал всё нужное для старта. Команд на этом
шаге не выполняй: окружение проверится само при первом сборе, а
человек ждёт текста, не прогресса в терминале.

Сначала представление — этим текстом, без пересказа своими словами,
чтобы у всех коллег знакомство было одинаковым:

```
Я собираю отзывы покупателей с площадок и отдаю книгу Excel:
сводка с темами негатива и цитатами, все отзывы, отдельно негатив,
карточки товаров.

Сейчас работают: Wildberries (последняя тысяча отзывов на карточку,
свежий срез), Ютека (лекарства и БАДы, полная глубина с 2018 года),
iRecommend (развёрнутые отзывы, не проверен на живых данных).
Ozon, Яндекс Маркет, Lamoda, Золотое Яблоко закрыты антиботом,
у Подружки своих отзывов нет, Мегамаркет, Еаптека и Отзовик ещё
не подключены.

Единица сбора — один бренд в одной категории: «водолазки ТВОЕ»,
а не «свитеры вообще». Если назовёте категорию, я покажу, какие
бренды и подкатегории есть в выдаче, и вы выберете. Сбор занимает
две-три минуты.
```

Затем один раунд вопросов средствами окружения (если инструмент
вопросов умеет несколько вопросов за раз — все три сразу, иначе
по одному, в этом порядке). Формулировки фиксированные:

1. **Площадка.** «С какой площадки собирать?» Варианты: Wildberries,
   Ютека, iRecommend, «другая — напишите какую». На другую — объясни
   по `references/blocked.md`, почему она не собирается, и предложи
   из рабочих.
2. **Что ищем.** «Что ищем: бренд, категория, конкретный товар или
   артикулы? Например „свитшоты ТВОЕ“, „АЦЦ“, „сыворотка с витамином C“.»
   Свободный ответ.
3. **Срез.** «Какие отзывы нужны?» Варианты: все отзывы (стандарт,
   рекомендуемый), только негатив 1–3 (`--stars 1-3`), за период
   (`--period`, границы уточни следующим вопросом), с фото
   (`--media photo`). Это единственное место, где о фильтрах спрашиваем
   сами: пользователь попросил провести его по вопросам, а не поставил
   задачу.

После ответов работа идёт по шагам 1–4 как с обычным запросом: разбор,
разведка с уточняющим вопросом, сбор, ответ по шаблону. Не повторяй
представление и не переспрашивай то, что уже ответили.

Если пользователь спросил «что ты умеешь» и явно не собирается ничего
собирать сейчас — представление без вопросов, и в конце одна строка:
«Скажите площадку и что искать — начнём».

### Шаг 1. Разобрать запрос

| Что сказал пользователь | Куда это идёт |
|---|---|
| название площадки | первый позиционный аргумент (`wb`, `uteka`, `irecommend`) |
| бренд, товар, категория | второй позиционный — поисковый запрос, в единственном числе и именительном падеже («по свитерам» → `"свитер"`): так ищут на площадке |
| артикулы WB | `--nm 119396077 148815731` |
| ссылки на товары Ютеки | `--url https://uteka.ru/product/...` |
| «за период», «с января», «в 2025» | `--period 2025-01..2025-08` |
| «негатив», «1–3 звезды», «плохие» | `--stars 1-3` |
| «с фото», «с видео» | `--media photo` / `video` / `any` |
| «где упоминают X, Y» | `--contains "X,Y"` |
| «развёрнутые», «от N символов» | `--min-len 500` |
| «о продавце», «о сервисе» | `--about seller` / `service` |
| «побольше», «пошире охват» | `--products 40` (WB), `--pages 2` |

Фильтры применяются только если пользователь их назвал. Не предлагай
их сам и не спрашивай о них: без фильтров собирается полный срез,
а сузить его в Excel коллега может и без нас. То же с объёмом: без
`--products` инструмент берёт 25 самых отзывных карточек — это
стандарт, и менять его стоит только по просьбе «побольше».

**Площадка не названа — спроси.** Не угадывай: данные с разных площадок
несопоставимы по глубине (WB отдаёт последнюю тысячу отзывов на карточку,
Ютека — всё с 2018 года). Предложи те, что работают, из таблицы ниже.
Если названа площадка из `references/blocked.md` — назови причину, по
которой она не собирается, и предложи рабочую. Не пробуй «на всякий
случай»: причины конкретные и проверенные.

### Шаг 2. Разведка и уточняющий вопрос

Единица сбора — **один бренд в одной продуктовой категории**. Не
«свитеры вообще» и не «весь ассортимент бренда». По запросу «свитер»
в выдаче около сотни брендов: без бренда датасет — смесь чужих товаров
и не отвечает ни на один вопрос. У бренда ТВОЕ 31 категория от футболок
до шлепанцев: сбор целиком смешивает претензии к обуви с претензиями
к белью, а болевые темы у них разные.

Поэтому до сбора запускается разведка:

```bash
collect wb "свитер" --explore
```

Она ничего не собирает — показывает, что в источнике реально есть
(подкатегории, бренды, продавцы, сколько карточек и отзывов в каждом),
и сама формулирует вопрос в блоке `СПРОСИТЬ У ПОЛЬЗОВАТЕЛЯ`. Логика
адаптивная:

- **брендов много** (запрос-категория) → вопрос «чей ассортимент нужен».
  После ответа повтори разведку с `--brand`, чтобы увидеть категории
  этого бренда, и задай второй вопрос — про категорию;
- **бренд один или задан** (запрос-бренд) → сразу вопрос «какая категория».

**Как задавать вопрос.** Средствами своего окружения для вопросов
пользователю (в Claude Code — `AskUserQuestion`, в Kilo —
`ask_followup_question`, в Cursor — инструмент вопросов агента), а не
текстом в ответе, за которым идёт работа. Если инструмента вопросов
нет — задай вопрос в ответе и закончи ход: следующий шаг только после
сообщения пользователя. Вопрос — тот, что сформулировала разведка; не переформулируй.
Варианты ответа — три верхних значения из разведки по числу отзывов,
с цифрами в том виде, как их напечатал инструмент («Водолазки —
12 карточек, 8 400 отзывов»), плюс вариант «другой — назову сам»:
инструменты вопросов обычно вмещают четыре варианта, а полный список
разведки пользователь и так видит в твоём сообщении. Дождись ответа
и только потом продолжай.

**Вариант «собрать всё вместе» не предлагается никогда.** Если
пользователь просит именно его — скажи, что получится смесь, и предложи
разбить на несколько прогонов по одной категории.

**Когда разведку можно пропустить:** названы и бренд, и узкая категория
(«свитшоты ТВОЕ»); даны артикулы `--nm` или ссылки `--url`; пользователь
уже выбрал разрез в предыдущем сообщении.

**Разведка есть только у Wildberries** — там в выдаче есть разрезы по
бренду и предмету. На Ютеке и iRecommend `--explore` не запускай:
собирай запросом целиком (там запрос — название препарата или
продукта, он уже узкий) и оговори в ответе, что сужения по бренду
не было.

Обычно на уточнение уходит один-два вопроса. Не растягивай: один
вопрос на шаг, без дополнительных «а ещё уточните».

### Шаг 3. Сбор

Выбранное пользователем идёт в аргументы: `--brand «ТВОЕ»`,
`--subject «Водолазки»`, `--supplier «название»`.

```bash
collect wb "свитер" --brand "ТВОЕ" --subject "Водолазки"
```

Каталог результата включает сужение — `out/wb/свитер--твое--водолазки/`
— поэтому разные срезы одного запроса не затирают друг друга.
Ориентир по времени на WB: около 5 секунд на карточку, 25 карточек —
две минуты. Если сбор дал ноль — см. раздел ниже, это четыре разных случая.

Сравнение брендов — несколько прогонов с разными `--brand` в одной
категории. Схема одна, книги сходятся без правок.

### Шаг 4. Ответ

Главный результат — книга Excel, путь к ней инструмент печатает
последней строкой. В ней четыре листа, всегда в этом порядке:

| Лист | Что внутри |
|---|---|
| Сводка | покрытие, смещение выборки, распределение оценок, темы негатива, цитаты, динамика |
| Отзывы | строка = отзыв, русская шапка, фильтр и закреплённая шапка |
| Негатив | те же колонки, только оценки 1–3 — с него обычно начинают читать |
| Карточки | товары в выборке, заявлено и собрано отзывов по каждому |

Рядом лежат `reviews.csv`, `products.csv` и `summary.md` — для склейки
датасетов и для тех, кто без Excel. В ответе пользователю их можно не
называть.

Ответ — строго по шаблону:

```
<Площадка>, <бренд> · <категория>

- N отзывов по M карточкам
- Заявлено площадкой: K — взято X%
- Негатив 1–3: Y% по данным площадки

Главное из сводки: <3–5 строк — верхние дефекты и разброс по карточкам>

Книга: out/<площадка>/<срез>/<площадка>--<срез>.xlsx
<одна оговорка, если она есть в сводке>
```

Цифры берутся из листа «Сводка» (он же `summary.md`), а доля негатива —
из таблицы «Смещение выборки», колонка «Карточки целиком». Почему —
в разделе о доверии к данным.

**Никакого анализа сверх сводки.** Не пиши на ходу скрипты, чтобы
посчитать темы, доли по карточкам или вытащить цитаты: всё это уже
считает инструмент одинаково при каждом запуске. Импровизированный
разбор каждый раз даёт другой результат, а это ломает сервис:
пользователь не может опереться на цифру, которую в следующий раз
посчитают иначе. Если просят разрез, которого в сводке нет, — это
заявка на доработку `scripts/core/report.py`, а не повод посчитать
один раз руками. Скажи об этом прямо.

## Площадки: что работает

| Аргумент | Площадка | Состояние |
|---|---|---|
| `wb` | Wildberries | ✅ проверен на живых данных, есть разведка |
| `uteka` | Ютека | ✅ проверен на живых данных |
| `irecommend` | iRecommend | ⚠️ написан по разведке, **не проверен** |

Остальные восемь площадок задания не подключены. Прежде чем обещать
сбор с них — прочитай `references/blocked.md`: часть закрыта
антиботом, а у одной отзывов физически нет.

Перед сбором с конкретной площадки прочитай `references/<площадка>.md`
— там её ограничения. Без этого легко выдать смещённую выборку
за полную.

## Чему в данных нельзя верить

Три правила, нарушение которых даёт правдоподобный, но неверный ответ.

**Не выдавай распределение оценок из листа «Отзывы» за распределение
по карточке.** На WB собранный срез показывает негатив втрое сильнее,
чем карточка целиком (6.6% против 2.2%). Для процентов есть таблица
«Смещение выборки» в сводке, она считается от данных площадки.

**Не строй динамику за годы по данным WB.** Он отдаёт последнюю
тысячу отзывов на карточку: у товара с 241 тысячей отзывов срез
покрывает месяцы, а не годы. У Ютеки глубина полная, с 2018 года —
там можно.

**Отделяй претензии к продукту от логистики, подделок и сервиса.**
Сводка делит негатив на темы грубой разметкой по словам. Это первый
срез, требующий проверки глазами, а не классификатор. Без разделения
бренд получает претензии за работу склада.

Подробнее — `references/analysis.md`.

## Если сбор дал ноль

Пустой результат — четыре разных случая, и путать их нельзя:

- **площадка закрыта** (`недоступен`, `не пробились`) — это не «отзывов
  нет». Скажи, что закрыта именно площадка, и предложи повторить позже;
- **сужение не совпало** — инструмент сам перечисляет, какие категории
  у бренда реально есть в этой выдаче. Передай список пользователю
  и спроси снова, не подбирай за него;
- **фильтры срезали всё** — в выводе видно `собрано N → после фильтров 0`.
  Предложи ослабить фильтр, а не пересобрать;
- **у товара действительно нет отзывов** — видно по колонке
  «Отзывов заявлено» на листе «Карточки».

## Установка скилла у коллег

Скилл самодостаточен: код, зависимости и справочники внутри. Склонировать
из GitLab в каталог скиллов — `.kilo/skills/reviews-collect/` для Kilo,
`.cursor/skills/reviews-collect/` для Cursor, `.claude/skills/reviews-collect/`
для Claude Code (Kilo и Cursor читают и его) — и один раз создать
окружение командой из раздела «Как вызывать инструмент». `.venv`
не копируется между машинами: в нём абсолютные пути. Имя каталога
должно совпадать с `name` в шапке этого файла.
